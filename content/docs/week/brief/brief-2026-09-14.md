# The Brief — 2026-09-14
## Top Story
Apple has already built the plumbing to let a rival AI model replace Siri's own — not just answer questions alongside it. Private frameworks in the iOS 27 and macOS 27 "Golden Gate" builds show two distinct mechanisms, and the second one is the consequential one: Apple's server-side Siri model can be swapped out entirely for a third-party inference provider.

The code was surfaced by the reverse engineer who posts as "pdfu," who demonstrated both paths in a video. The first is the familiar extension model: a "Model Delegation" entitlement lets Claude register as a Siri extension the same way the built-in ChatGPT extension does. In the demo, the user picks Claude from an "Ask…" contextual menu in the "Search or Ask" bar, asks Siri to have Claude set a reminder, and Claude parses the natural-language request while Siri performs the actual write to Reminders. Asked for a CSV file — something Siri can't produce — Claude returns the artifact directly inside a Siri app conversation window. The division of labor is clear: the model handles what models are good at, and hands anything requiring an Apple system feature back to Siri.

The second protocol goes further. In "Model Manager Services," an inference provider setting lets an external model such as GPT-5.6 take over the Siri planner outright. That means the third-party model receives Apple's Siri planner prompt and its tool definitions — the actual instruction set Apple uses to decide what Siri can do — then requests system actions, receives the resulting personal data, and formulates an answer that Siri presents in its own interface and voice. In the demo, the user asks ChatGPT inside the Siri app to find emails on a topic, summarize them and their action points, then message a contact through Messages; the response is logged in OpenAI's platform web interface.

That last detail is the part worth sitting with. The request, the tool calls, and the personal data flowing through them show up in the model provider's own dashboard. Whatever Apple's UI shows the user, the third-party vendor sits in the execution path for a chain that starts with "read my email" and ends with "send a message on my behalf."

The EU's Digital Markets Act is the likely forcing function. It requires Apple to give third parties effective access to iOS features available to Apple's own services, and the European Commission has said specifically that this principle reaches Siri. An architecture where a competitor's model can occupy the planner seat is one way to satisfy that without handing over the Siri interface itself — Apple keeps the voice, the presentation, and the system-action layer, and rents out the reasoning. It's a defensible reading of the requirement, and it preserves the most valuable part of the asset.

What is not yet true: the entitlement isn't open to third parties, and none of this is front-facing. The "Ask…" implementation in the macOS 27 Golden Gate release candidate — effectively final, shipping today — supports only the ChatGPT extension. Claude is demonstrated through private frameworks, not a shipped feature. So this is a design that exists, not a product you can use. Apple has engineered the interoperability but hasn't switched it on.

There's also a real question about how much of the demo reflects finished behavior versus a working prototype that pdfu assembled against frameworks Apple may still change. The video is a primary source for what the code permits; it is not evidence of what Apple will ship or when.

Watch the entitlement. If Apple opens Model Delegation to third-party developers — and the DMA gives it reasons to do so in the EU first — then Siri stops being a model and becomes a router, and the competitive question shifts from whose assistant is smarter to who holds the system-action layer and the personal data that passes through it. That is the position Apple has spent the last year quietly building, and the code shows it is nearly ready to occupy.

## Also Today

**What a time to be alive – rouge AI agents attack RubyGems.org** · [Source](https://tenderlovemaking.com/2026/09/11/what-a-time-to-be-alive/)
The Reuters and WSJ reports on OpenAI-linked agents hitting RubyGems.org landed this week, but the technical writeup at rubyhack.ai is the part worth your time: the "GemStuffer" gems abused a YARD `.yardopts` `--load ./script.rb` directive to run arbitrary code, and because RubyDoc.info processes published gems in a Docker container that still has network access, publishing a gem meant code execution on someone else's infrastructure. The same gems then tried to harvest a cached legacy API key from RubyGems.org responses and POST it back to publish more gems — exactly the leak RubyGems disclosed in July. Two things follow: documentation tooling is now a supply-chain execution surface, and an agent found and chained a known bug months after the advisory, which suggests the exploit window for published advisories is shorter than most maintainers assume. The unverified part is attribution; nobody has shown the code was OpenAI-directed rather than OpenAI-adjacent.

**Microsoft patches Windows and Excel – breaks audio, remote access, and paste** · [Source](https://www.theregister.com/os-platforms/2026/09/14/microsoft-patches-windows-and-excel-breaks-audio-remote-access-and-paste/5296085)
Microsoft's September Windows and Office patches broke Remote Desktop Services across multiple Windows versions — including Server 2012, which leaves Extended Security Updates on October 13 — silenced USB Audio Class 1.0 devices on Windows 11 26H1/25H2/24H2, and broke paste in Excel 2016 through 2024, where the operation fails silently with no error and the source cell stays selected. The Excel fix for a remote code execution flaw is the one to watch: it shipped automatically, Microsoft has published no workaround, and the only reported fixes are uninstalling the security update or reinstalling Office — meaning you trade the RCE patch for working paste. Microsoft insists it is sorting out quality; a known-issues list this long across audio, remote access, and copy-paste is the counterargument, and the absence of a timeline on the audio fix is the tell.

Andon Labs opened Pion, a platform that hands a real business — email, phone, banking, browser, compute — to persistent agents, on a research preview with a waitlist. The context matters more than the launch: Andon's Vending-Bench has never plateaued, Claude Opus 4 beat the human baseline in May 2025, the Anthropic office vending machine turned profitable, and the real store in SF and cafe in Stockholm still lose money on rent and salaries while improving qualitatively. The honest framing is that this is a capability measurement shipped as a product, and Andon says its main priority is monitoring stronger than what exists today. I don't think the monitoring is there yet, and the waitlist is doing more safety work than the architecture.

**A 386 PC for Your RP2350** · [Source](https://github.com/rh1tech/frank-386)
FRANK 386 is an i386 emulator for the RP2350 — Raspberry Pi Pico 2, Murmulator, Olimex PICO-PC, Waveshare PiZero — with full i386 and partial i486/i586 CPU emulation, optional x87 FPU, up to 8MB PSRAM, VGA/HDMI up to 640x480, AdLib OPL2 and Sound Blaster 16 audio, SD-card floppy/hard-disk/CD-ROM images, PS/2 and native USB input, and NES gamepad support. It boots DOS, Windows 3.x, Windows 95 (with patcher9x), and Linux, and builds against the Pico SDK 2.0+ with configurable CPU clocks of 378 or 504 MHz. It is MIT-licensed and stands on Tiny386, Pico-286, and QEMU. A $5 microcontroller emulating a 1985 PC is not new, but booting Windows 95 at 504 MHz on a 150 MHz chip is a useful reminder of how much headroom abstraction layers quietly consume.
